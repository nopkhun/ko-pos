## 1. ปัญหาที่โมดูลนี้แก้ และทางที่ตัดทิ้งไปแล้ว

Odoo อยู่บนคลาวด์ (HTTPS, Hostinger VPS) ส่วนเครื่องพิมพ์ความร้อนอยู่บน WiFi ของร้าน
**เบราว์เซอร์เปิด socket ไปหาเครื่องพิมพ์ไม่ได้ และ Odoo บน VPS ก็ไปหาไม่ได้เหมือนกัน**
ที่เหลือคือกด Ctrl+P ทุกใบ ซึ่งไม่ใช่การพิมพ์ใบเสร็จของร้านอาหาร

ทางอื่นที่พิจารณาแล้วตัดทิ้ง — อย่าเสียเวลารื้อใหม่โดยไม่มีข้อมูลใหม่:

| ทาง | ทำไมใช้ไม่ได้ |
| --- | --- |
| `pos_epson_printer` / ePOS ในตัว Odoo | Odoo 19 **Community** ไม่มีโมดูลนี้ และทางนี้ให้เบราว์เซอร์ยิง HTTPS ตรงไปที่เครื่องพิมพ์ |
| IoT Box | เป็นของ Odoo Enterprise ต้องซื้อกล่อง + subscription |
| ES-8803WA คุยภาษา ePOS ได้ไหม | ไม่ได้ เป็น ESC/POS ธรรมดาบน TCP 9100 ไม่มี ePOS/HTTPS |
| พิมพ์จากเบราว์เซอร์ (kiosk printing / QZ Tray) | ครอบได้แค่บางเครื่อง — หน้าร้านมี Windows Chrome, Android 7 Chrome 119, Sunmi D2s Plus และ iPad ปะปนกัน |

คำตอบคือ **ย้ายงานพิมพ์ไปไว้ที่เครื่อง PC ในร้าน** เครื่องนั้นอยู่วงเดียวกับเครื่องพิมพ์อยู่แล้ว
และ "ดึง" งานจาก Odoo ออกไปเอง (ไม่ต้องเปิดพอร์ตเข้าร้านแม้แต่พอร์ตเดียว)

## 2. ภาพรวมระบบ

```
   เบราว์เซอร์ POS  (Windows Chrome / Android / Sunmi D2s Plus / iPad Safari)
        │  render ใบเสร็จ → canvas → PNG   (pixelRatio 2 เพื่อให้สระ/วรรณยุกต์ไทยไม่เละ)
        │  rpc:  POST /ko_print/job        (auth='user', jsonrpc, ส่งแค่ printer_id + รูป)
        ▼
   ┌───────────────────────────────────────────────────────────────┐
   │  Odoo 19  ·  https://kodoo.viakuma.com  (Hostinger VPS)       │
   │                                                               │
   │   ko.print.agent   token 43 ตัวอักษร, last_seen, is_online    │
   │   ko.print.job     queued → sent → done | error               │
   │        host / port / paper_width อ่านจาก pos.printer เท่านั้น  │
   └───────────────────────────────────────────────────────────────┘
        ▲  HTTPS + `Authorization: Bearer <token>`   (ขาออกจากร้านอย่างเดียว)
        │     POST /ko_print/agent/ping   หัวใจเต้น → last_seen
        │     POST /ko_print/agent/poll   ขอรับงาน (FOR UPDATE SKIP LOCKED)
        │     POST /ko_print/agent/ack    แจ้งผล done / error
        │
   ┌────┴──────────────────────────────────────┐
   │  PC ที่ร้าน (Windows, Task Scheduler)      │
   │  ko_print_agent.exe — poll ทุก ~1 วินาที   │
   │  PNG → ESC/POS raster (576 dots @80mm)     │
   └────┬──────────────────────────────────────┘
        │  TCP 9100  บน LAN ของร้าน
        ▼
   EASY PRINT ES-8803WA (ใบเสร็จลูกค้า 80 มม.)  +  เครื่องพิมพ์ครัว (ถ้ามี)
```

สิ่งที่ **ไม่** เปลี่ยน: จอครัว (KDS) ไม่เกี่ยวกับเครื่องพิมพ์เลย กฎเดิมใน `../AGENTS.md`
ยังอยู่ครบ — ใบครัวที่พิมพ์กระดาษกับบอร์ดครัวเป็นคนละระบบและไม่ขึ้นแก่กัน

## 3. สร้างตัวแทนพิมพ์ (Agent) + Token ใน Odoo

**ต้องเป็นผู้จัดการ POS** (`point_of_sale.group_pos_manager`) — พนักงานทั่วไปไม่เห็นเมนูนี้

1. **Point of Sale ▸ Configuration ▸ Print Agents** (ไทย: *ตัวแทนพิมพ์*) → **New**
2. ตั้งชื่อให้รู้ว่าเครื่องไหน เช่น `คอมหน้าเคาน์เตอร์ ร้านชอบแกง`
3. บันทึก — ระบบสร้าง **Token** ให้เองอัตโนมัติ (`secrets.token_urlsafe(32)` = 43 ตัวอักษร)
   กดปุ่มคัดลอกข้างช่อง Token
4. Token นี้ = รหัสผ่าน ใครถือก็ **อ่านรูปใบเสร็จของร้านนี้ได้ทั้งหมด** ห้ามส่งผ่านแชตสาธารณะ
   เก็บที่เดียวคือ `CREDENTIALS.local.md` (local only)
   > ตอนนี้ยังไม่ได้ออก token ของ production — ใน `CREDENTIALS.local.md` ยังเป็นช่องว่าง
   > เมื่อออกจริงเมื่อไหร่ ให้บันทึกลงไฟล์นั้นทันที อย่าปล่อยไว้ในแชต
5. หน้าฟอร์มบอกสถานะให้เอง: **Online / Last Seen / Agent Version / Last IP** และปุ่ม
   **Queued** ที่ลัดไปดูงานพิมพ์ของ agent ตัวนี้

หนึ่งร้าน = หนึ่ง agent ก็พอ (agent ตัวเดียวพิมพ์ได้หลายเครื่องพิมพ์) `company_id` บังคับเสมอ
และมี `ir.rule` แบบ global กันไม่ให้ข้ามบริษัท

## 4. ตั้งค่าเครื่องพิมพ์ — ใบเสร็จลูกค้า vs ใบครัว

เครื่องพิมพ์ทุกตัวคือ record ของ `pos.printer` เลือกชนิดเป็น
**KO Print Agent (ESC/POS over network)** แล้วกรอก 4 ช่องนี้ (ช่องจะโผล่เมื่อเลือกชนิดนี้เท่านั้น):

| ช่อง | ค่า |
| --- | --- |
| Print Agent | agent จาก §3 (บริษัทเดียวกันเท่านั้น) |
| Printer IP / Host | IP ของเครื่องพิมพ์บน LAN ร้าน เช่น `192.168.1.50` — **ตั้ง Static IP / DHCP Reservation ที่เราเตอร์** |
| Printer Port | `9100` (ค่าเริ่มต้น) |
| Paper Width | `80` มม. สำหรับ ES-8803WA (มี `58` ให้เลือกด้วย) |

ถ้าเลือกชนิด `ko_cloud` แล้วไม่ใส่ agent หรือไม่ใส่ IP ระบบจะไม่ยอมบันทึก (ValidationError)

### 4.1 ใบเสร็จลูกค้า

**ตั้งค่า POS → Connected Devices → KO Print Agent → Receipt Printer**
(`pos.config.ko_receipt_printer_id`) เลือกเครื่องพิมพ์ใบเสร็จของร้านนั้น
มีสวิตช์ **Open Cash Drawer** (`ko_cashdrawer`) ถ้าลิ้นชักเงินต่อกับเครื่องพิมพ์ตัวนี้ —
เปิดแล้วทุกทางที่ POS สั่งเปิดลิ้นชัก (หน้าจ่ายเงิน, ปิดรอบขาย, เงินเข้า/ออก) จะส่ง pulse ไปจริง

### 4.2 ใบครัว

**ไม่ต้องตั้งอะไรเพิ่มในโมดูลนี้** ใบครัวยังเดินทางเดิมของ Odoo คือ `pos.config.printer_ids`
(ตั้งค่า POS → Preparation) แค่เพิ่มเครื่องพิมพ์ครัวชนิด `ko_cloud` เข้าไปในรายการนั้น
พร้อมหมวดสินค้าที่ต้องพิมพ์ ระบบก็ส่งให้เอง

**เครื่องพิมพ์ใบเสร็จถูกกันออกจากงานครัวโดยอัตโนมัติ** — มันถูกโหลดเข้า POS เพื่อให้
many2one ชี้ถึงได้เท่านั้น ถ้าไม่ได้อยู่ใน `printer_ids` ด้วย จะถูกคัดออกจาก
`unwatched.printers` ก่อนใช้งาน ใบครัวจึงไม่พรวดออกที่เครื่องหน้าแคชเชียร์

## 5. ติดตั้งโปรแกรมบนเครื่อง PC ที่ร้าน

ขั้นตอนละเอียด (ภาษาไทย ให้เจ้าของร้านอ่านเองได้) อยู่ที่ **`../print-agent/README.th.md`**
และให้ทดสอบเครื่องพิมพ์ก่อนตาม `../print-agent/phase0/README.th.md`

สรุปสั้น ๆ ว่าเกิดอะไรขึ้นบ้าง:

1. คัดลอกโฟลเดอร์โปรแกรมไปที่เครื่องร้าน เช่น `C:\KO\print-agent\`
2. คัดลอก `ko_print_agent.example.ini` เป็น `ko_print_agent.ini` แล้วใส่ `url` + `token`
3. ทดสอบ `.\ko_print_agent.exe --ping` → ต้องขึ้น `[OK] Ping succeeded`
4. ทดสอบพิมพ์จริง `.\ko_print_agent.exe --test-print 192.168.1.50`
5. ติดตั้งให้รันเอง: PowerShell (Run as Administrator) → `.\build\install_service.ps1`
   → Windows Task Scheduler รันตอนเปิดเครื่อง, รีสตาร์ทเองถ้าค้าง, และล็อกสิทธิ์ไฟล์ ini
   ให้อ่านได้เฉพาะบัญชีนี้กับ Administrators
6. ปิด Sleep ของเครื่องอย่างน้อยช่วงเปิดร้าน — เครื่องหลับ = ไม่มีใบเสร็จ

> ฝั่ง agent มีด่านความปลอดภัยของตัวเอง: ปฏิเสธปลายทางที่ไม่ใช่ IP วง LAN
> (ไม่ยอม public IP, ไม่ยอม loopback ถ้าไม่เปิด flag) และยอมเฉพาะพอร์ตใน `allowed_ports`
> (ค่าเริ่มต้น `9100`) — เพิ่มเครื่องพิมพ์ครัวที่ใช้พอร์ตอื่นต้องเติมพอร์ตในไฟล์ ini ด้วย

## 6. "ออนไลน์" คือ ping มาภายใน 20 วินาที

- agent ping/poll ทุก ๆ ประมาณ 1 วินาที ทุกครั้งที่คุยกันสำเร็จจะอัปเดต `last_seen`
  (เขียนจริงแบบหรี่ไว้ที่ 5 วินาทีครั้ง ไม่งั้นแถวนี้ถูกเขียนวินาทีละครั้งโดยไม่ได้ข้อมูลใหม่)
- `is_online` = `last_seen` ห่างจากตอนนี้ **ไม่เกิน 20 วินาที** (ยอมให้ poll หลุดได้ 2–3 ครั้ง)
- ถ้า **ออฟไลน์** `/ko_print/job` จะตอบ `agent_offline` และ **ไม่สร้างงานพิมพ์เลย** —
  ตั้งใจให้เป็นแบบนั้น คิวใบเสร็จที่ค้างแล้วพรวดออกพร้อมกันตอนเย็นแย่กว่าไม่มีใบเสร็จ
- POS จะ **พิมพ์ผ่านเบราว์เซอร์ให้แทนทันที** พร้อม toast ภาษาไทยว่าตัวแทนพิมพ์ออฟไลน์
  (เฉพาะ *ใบเสร็จลูกค้า* เท่านั้น — ใบครัวไม่มี fallback เพราะพิมพ์ออกเครื่องหน้าเคาน์เตอร์ก็ไม่ช่วยใคร)

## 7. แก้ปัญหา — เริ่มที่ Print Jobs เสมอ

**Point of Sale ▸ Configuration ▸ Print Jobs** (กรองวันนี้ให้อัตโนมัติ) อ่านคอลัมน์ **Status**:

| สถานะ | แปลว่า | ทำอะไรต่อ |
| --- | --- | --- |
| **Queued** | สร้างแล้ว รอ agent มารับ | ถ้าค้างเกินไม่กี่วินาที = agent ไม่ได้ poll → เช็คเครื่อง PC / งาน Task Scheduler / log ที่เครื่องร้าน |
| **Sent to Agent** | agent รับไปแล้ว ยังไม่ตอบกลับ | ค้างเกิน **60 วินาที** ระบบจะคืนเข้าคิวเอง (`attempts` +1) ครบ **3 ครั้ง** แล้วยังไม่ ack → ตีเป็น Failed |
| **Printed** | agent ยืนยันแล้วว่าพิมพ์ออก | — |
| **Failed** | agent แจ้ง error หรือหมดโควตา retry | เปิด record อ่านช่อง **Error**; ดูรูปในฟอร์มได้ว่าที่ส่งไปหน้าตาเป็นอย่างไร |

ฟอร์มงานพิมพ์เป็น read-only ตั้งใจ — งานถูกสร้างโดย POS และถูกกินโดย agent ไม่มีอะไรให้แก้ด้วยมือ
งานที่เก่ากว่า **7 วัน** ถูกลบอัตโนมัติโดย cron *KO Print: remove old print jobs* (วันละครั้ง)

### ถ้าไม่มีงานพิมพ์เกิดขึ้นเลย

แสดงว่าถูกปฏิเสธตั้งแต่ `/ko_print/job` — POS จะขึ้นข้อความไทยและเข้ากล่อง retry ปกติของ Odoo
รหัสเหตุผลที่เป็นไปได้:

| reason | สาเหตุ |
| --- | --- |
| `agent_offline` | agent ไม่ได้ ping มาใน 20 วินาที (ดู §6) |
| `no_agent` | เครื่องพิมพ์ตัวนั้นยังไม่ได้ผูก agent |
| `not_a_cloud_printer` | ไม่ใช่ชนิด `ko_cloud` หรือคนละบริษัทกับผู้ใช้ |
| `printer_not_in_config` | เครื่องพิมพ์ไม่ได้อยู่ใน `printer_ids` และไม่ใช่ `ko_receipt_printer_id` ของ POS นั้น |
| `image_too_large` | รูป base64 เกิน 2 MB |
| `nothing_to_print` | ไม่ใช่ PNG จริง / base64 พัง / ไม่มีทั้งรูปและคำสั่งเปิดลิ้นชัก |

### ที่เครื่องร้าน

- log อยู่ที่ `ko_print_agent.log` ข้าง ๆ ตัวโปรแกรม (หมุนไฟล์เอง ~5 MB)
- `destination_not_allowed` / `destination REJECTED` ใน log = ปลายทางไม่ผ่านด่านของ agent เอง
  มักเป็นเครื่องพิมพ์ตัวใหม่ที่ใช้พอร์ตอื่น → เติมใน `allowed_ports` ของ `ko_print_agent.ini`
- `token ผิด` = token ใน ini ไม่ตรงกับใน Odoo (ดู §8)

## 8. เปลี่ยน Token เมื่อสงสัยว่าหลุด

Token คือสิทธิ์อ่านงานพิมพ์ทั้งหมดของร้านนั้น (รูปใบเสร็จ = ข้อมูลลูกค้า/ยอดขาย)
ถ้าหลุดเข้าแชต, อีเมล, เครื่องที่ไม่ไว้ใจ หรือพนักงานที่ถือลาออก → เปลี่ยนทันที

1. Odoo: **Point of Sale ▸ Configuration ▸ Print Agents** → เปิด agent → ปุ่ม
   **Regenerate token** (มีกล่องยืนยันเตือนว่า agent จะหยุดทำงานจนกว่าจะตั้งค่าใหม่)
2. เครื่องที่ร้าน: แก้ `ko_print_agent.ini` ใส่ token ใหม่
3. สั่งเริ่มงานใหม่: `Start-ScheduledTask -TaskName 'KO Print Agent'` (หรือรีสตาร์ทเครื่อง)
4. `.\ko_print_agent.exe --ping` ต้องผ่าน แล้วเช็คว่า **Online** กลับมาในหน้า Odoo
5. อัปเดต `CREDENTIALS.local.md` (local only — ห้าม commit)

ระหว่างขั้น 1–3 ใบเสร็จจะตกไปทาง fallback ของเบราว์เซอร์ ไม่มีงานพิมพ์หาย
ถ้าเครื่อง PC หายไปเลย ให้ archive agent ตัวนั้น (งานพิมพ์ของมันถูกลบตาม `ondelete='cascade'`
เมื่อลบ agent จริง ๆ)

## 9. โมเดลความปลอดภัย (อ่านก่อนแก้ controller)

**ฝั่ง Odoo**

- `ko.print.agent` และ `ko.print.job` เปิดสิทธิ์ให้ **ผู้จัดการ POS เท่านั้น** —
  แคชเชียร์ไม่มีสิทธิ์ read/create งานพิมพ์ผ่าน ORM เลย
- งานพิมพ์เกิดได้ทางเดียวคือ `/ko_print/job` ซึ่งตรวจก่อนแล้วค่อย `sudo().create()`:
  บริษัทของเครื่องพิมพ์ต้องเป็นบริษัทของผู้เรียก, `config_id` ต้องมองเห็นได้ตาม record rule ของผู้เรียก
  และเครื่องพิมพ์ต้องเป็นเครื่องที่ POS นั้นประกาศไว้จริง (`printer_ids` หรือ `ko_receipt_printer_id`)
- **host / port / paper width อ่านจาก `pos.printer` เสมอ ไม่เคยอ่านจาก request body** —
  ถ้าปล่อยให้ body ระบุปลายทางได้ endpoint นี้จะกลายเป็น open relay ยิงเข้า LAN ของร้าน
  (นี่คือช่องโหว่ที่ `037be03` ปิด อย่าเผลอเปิดคืน)
- รูปต้องเป็น `str`, base64 ถูกต้อง, ขึ้นต้นด้วย PNG magic และไม่เกิน **2 MB**
- token: ยาว 43 ตัวอักษรเท่านั้น ตรวจความยาวก่อนแตะฐานข้อมูล แล้วเทียบด้วย
  `hmac.compare_digest` (ไม่ใช่ `==`) ทุก response ที่ไม่ผ่านตอบ `401 {"error":"unauthorized"}` เหมือนกันหมด
- `ack` รับเฉพาะงานที่อยู่สถานะ `sent` เท่านั้น — ack ซ้ำ/ย้อนหลังจะไม่สามารถทำให้ใบที่เพิ่งเข้าคิว
  กลายเป็น "พิมพ์แล้ว"
- งานที่ค้าง `sent` เกิน 60 วินาทีถูกคืนคิว สูงสุด 3 ครั้ง แล้วจอดเป็น `error`
- `ir.rule` แบบ global บังคับ `company_id` ทั้งสองโมเดล — ร้านหนึ่งไม่มีวันเห็นใบเสร็จของอีกร้าน
- `_touch` (heartbeat) หรี่ไว้ที่ 5 วินาที และใน `poll` ถูกเขียนหลังเคลมงานเสร็จ เพื่อไม่ถือ row lock นาน
- งานพิมพ์เก็บ 7 วันแล้วลบด้วย cron ที่รันเป็น `base.user_root`

**ฝั่งเครื่องร้าน (ด่านที่สอง — เผื่อ Odoo/token ถูกยึด)**

- agent ปฏิเสธปลายทางที่ไม่ใช่ IP ส่วนตัว (private/link-local) และปฏิเสธพอร์ตที่ไม่อยู่ใน
  `allowed_ports` โดยไม่สนว่า Odoo สั่งอะไรมา — ค่าเริ่มต้น hostname ก็ไม่รับ ต้องเป็น IP
- ทุก connection เป็น **ขาออก** ทั้งหมด ไม่มีการเปิดพอร์ตขาเข้าที่ร้านเลย
- `install_service.ps1` จำกัดสิทธิ์อ่าน `ko_print_agent.ini` ไว้ที่เจ้าของบัญชี + Administrators

## 10. ยังไม่ได้พิสูจน์ (อย่าพูดว่า "ใช้ได้แล้ว")

ที่พิสูจน์แล้ว: module tests **0 failed, 0 error(s) of 24 tests** บน Odoo 19 + Postgres 17
แบบใช้แล้วทิ้ง และ browser pass ที่ยืนยันว่า POS โหลดได้ไม่มี console error ใหม่,
`createPrinter`/`hardwareProxy` คืนค่าเป็น `KoCloudPrinter` ทั้ง shop และ restaurant config,
canvas เป็น 2x และใบเสร็จ/คำสั่งเปิดลิ้นชัก/ใบครัว ไปถึง agent จำลองเป็น PNG จริงและถูก ack

ที่ **ยังไม่ได้** ทำ:

1. **ยังไม่ deploy** — ต้องเติม `ko_pos_cloud_print` ในรายการโมดูลของ service `odoo-upgrade`
   (`vps-compose-git.yaml` ใน `deploy-secrets.zip`) ก่อน ไม่งั้นโมดูลไม่มีวันถูกติดตั้ง
   ดู `RUNBOOK-deploy.md` และรอเจ้าของอนุมัติ
2. **ไม่เคยพิมพ์กับ ES-8803WA จริง** — ความคมของภาษาไทยที่ 576 dots, การตัดกระดาษ,
   และ pulse ลิ้นชัก ยังเป็นทฤษฎีล้วน
3. **ยังไม่ได้ทดสอบ 4 อุปกรณ์จริง** (Windows Chrome / Android 7 Chrome 119 /
   Sunmi D2s Plus / iPad Safari) — ต้องพิสูจน์ว่า canvas → PNG ทำงานเหมือนกันทุกตัว
4. **ยังไม่ได้ออก token ของ production** และยังไม่ได้ลงโปรแกรมที่เครื่องร้าน
5. **`.exe` จาก PyInstaller ยังไม่เคย build/รันบน Windows จริง** — สคริปต์ build มีแล้วแต่ยังไม่ได้ใช้
6. **ยังไม่มี rate limit ที่ Traefik สำหรับ `/ko_print/agent/`** — ตอนนี้ token ที่ผิดถูกปฏิเสธเร็ว
   แต่ไม่มีอะไรจำกัดจำนวนครั้งที่ยิงเข้ามา (ห้ามแก้ Traefik label เอง — `../AGENTS.md` §7 ข้อ 4)
