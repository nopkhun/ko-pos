# RUNBOOK — จอลูกค้า (Customer Display) + โฆษณา + Beam QR

> โมดูล: `ko_pos_customer_display` (จอ + โฆษณา) และ `ko_pos_beam_bolt` ≥ 19.0.5.0.0 (Beam QR)
> จอลูกค้าต่อยอดจาก Customer Display ในตัวของ Odoo 19 — การ sync ออเดอร์เป็นของ Odoo
> ส่วน layout ไทย, โฆษณา, และ QR เป็นของเรา

## 1. เปิดจอลูกค้า (พนักงาน)

1. เปิด POS ตามปกติ (`/pos/ui`)
2. เมนูมุมขวาบน (⋮ / เมนูหลัก) → **Customer Display / จอลูกค้า**
3. Odoo จะแสดง QR ของลิงก์จอลูกค้า:
   - **เครื่องเดียวกัน** — เปิดเป็นหน้าต่างใหม่ แล้วลากไปจอที่สอง
   - **อุปกรณ์อื่น** (แท็บเล็ต/จอ TV ที่มี browser) — สแกน QR ด้วยอุปกรณ์นั้น
     หน้าจอเปิดได้เลยโดย **ไม่ต้อง login** (ลิงก์มี access token ของจุดขายฝังอยู่)
4. จอปรับ layout เองตามอุปกรณ์: แนวตั้ง = คอลัมน์เดียว, แนวนอน/TV = รายการซ้าย + ยอดรวมขวา
   ขนาดตัวอักษรสเกลตามขนาดจออัตโนมัติ ไม่มีอะไรต้องตั้ง

ลิงก์จอผูกกับ *เครื่อง POS ที่เปิดมัน* (device UUID ใน browser ของเครื่องแคชเชียร์)
ถ้าเปลี่ยนเครื่องแคชเชียร์ ให้เปิดลิงก์ใหม่จากเมนูเดิมบนเครื่องใหม่

## 2. สื่อโฆษณาเมื่อจอว่าง

- จัดการไฟล์: **Point of Sale → ตั้งค่า → สื่อโฆษณาจอลูกค้า**
  - อัปโหลดได้ทั้ง **ภาพนิ่ง** (JPG/PNG/WebP/GIF) และ **วิดีโอ** (MP4 H.264 / WebM)
  - ไฟล์ละไม่เกิน **50 MB** — วิดีโอแนะนำ 1080p พอ จอลูกค้าไม่ต้อง 4K
  - เลือกจุดขาย, ลากลำดับ, ปิดชั่วคราวด้วยสวิตช์ "ใช้งาน" ได้
  - ภาพนิ่งตั้งเวลาเฉพาะภาพได้ (0 = ใช้ค่ากลาง) ส่วน**วิดีโอเล่นจนจบเสมอ และไม่มีเสียง**
    (browser บังคับ: วิดีโอที่เล่นเองต้อง mute)
- ตั้งเวลา: **ตั้งค่า POS → โฆษณาบนจอลูกค้า (KO)** — วินาทีก่อนเริ่มเล่นหลังจอว่าง (ค่าเริ่มต้น 15)
  และวินาทีต่อภาพนิ่ง (ค่าเริ่มต้น 8)
- พฤติกรรม: จอไม่มีออเดอร์ค้างเกินเวลาที่ตั้ง → เล่นสื่อวนตามลำดับ
  พนักงานคีย์รายการเมื่อไหร่ → ตัดกลับหน้าออเดอร์ทันทีแม้วิดีโอยังไม่จบ
- **เปลี่ยนสื่อแล้ว จอที่เปิดค้างอยู่ต้องรีเฟรชหนึ่งครั้ง** (playlist โหลดตอนเปิดหน้า)

### ขนาดคอนเทนต์ที่แนะนำ

ข้อความชุดนี้ขึ้นในหน้าตั้งค่า POS, ฟอร์มสื่อ และหน้าว่างของเมนูสื่อแล้ว
ตั้งแต่ `ko_pos_customer_display` **19.0.1.1.0** — ที่นี่คือฉบับเต็ม

| จอลูกค้า | ขนาดไฟล์ที่ควรทำ | อัตราส่วน |
| --- | --- | --- |
| จอแนวนอน / TV | **1920 × 1080 px** | 16:9 |
| จอแนวตั้ง / แท็บเล็ตตั้ง | **1080 × 1920 px** | 9:16 |

- สื่อวางแบบ `object-fit: contain` — **ไม่ครอปภาพทิ้ง** แต่ถ้าอัตราส่วนไม่ตรงกับจอจริง
  จะย่อให้พอดีและเหลือ**ขอบดำ** ทำไฟล์ให้ตรงอัตราส่วนของจอที่ติดตั้งจริงเสมอ
- เว้นขอบปลอดภัยรอบ ๆ ~5% อย่าวางข้อความสำคัญชิดขอบ
- ภาพนิ่ง: JPG / PNG / WebP / GIF — แนะนำไม่เกิน **2 MB** ต่อภาพ (โหลดเร็ว จอไม่กระตุก)
- วิดีโอ: MP4 (H.264) หรือ WebM — 1080p, 24–30 fps, ยาว **10–30 วินาที**,
  **ไม่เกิน 50 MB** (เพดานจริงของระบบ เกินกว่านี้ระบบปฏิเสธพร้อมบอกขนาดไฟล์)
- วิดีโอไม่มีเสียงเสมอ — ออกแบบให้สื่อสารด้วยภาพหรือซับไตเติล

## 2.1 จอกลับหน้าต้อนรับเมื่อพนักงานออกจากหน้าออเดอร์

ตั้งแต่ **19.0.1.1.0** (ขึ้น production แล้ว 2026-08-29): จอลูกค้าจะแสดงรายการก็ต่อเมื่อพนักงานอยู่ในหน้าที่เกี่ยวกับออเดอร์
(`ProductScreen`, `PaymentScreen`, `ReceiptScreen`, `FeedbackScreen`, `SplitBillScreen`,
`TipScreen`) — ออกไปหน้าโต๊ะ, รายการบิล, หน้า login หรือหน้าพักจอเมื่อไหร่
จอกลับหน้า **ยินดีต้อนรับ** ทันที แล้วเข้าโหมดโฆษณาตามเวลาที่ตั้งไว้
กลับเข้าโต๊ะเดิมก็เห็นรายการเดิมทันทีเหมือนเดิม

ก่อนหน้านี้จอ**ค้างรายการของบิลก่อนหน้า**ค้างไว้ เพราะ Odoo ส่งข้อมูลไปจอเฉพาะตอน
"ออเดอร์ที่เลือก" เปลี่ยน และไม่เคยล้างออเดอร์ที่เลือกตอนกลับไปหน้าโต๊ะ (ดู `docs/GOTCHAS.md`)

## 3. Beam QR บนจอลูกค้า

### ตั้งค่า (ครั้งเดียว, ผู้จัดการ)

1. **Point of Sale → Configuration → Payment Methods → สร้างใหม่**
2. ตั้งชื่อ เช่น `QR พร้อมเพย์ (จอลูกค้า)` — สมุดบัญชี: ธนาคาร
3. `การผสานรวม` = เครื่องรูดบัตร แล้วเลือก `ผสานรวมกับ` = **Beam QR (จอลูกค้า)**
4. กรอก **Merchant ID / API Key** — ใช้ชุดเดียวกับที่ Pair เครื่อง Bolt+ ได้เลย ไม่ต้อง Pair เครื่อง
5. ประเภท QR ระบบตั้งเป็น QR พร้อมเพย์ให้อัตโนมัติ (ใบเดียวรองรับแอปธนาคาร + e-wallet)
6. `หมดเวลาใน (วินาที)` = อายุของ QR (90–600, ค่าเริ่มต้น 120)
7. เพิ่มวิธีชำระเงินนี้เข้าไปในจุดขายที่ต้องการ

ทดสอบครั้งแรกให้เปิด **Beam Playground (ทดสอบ)** ก่อน แล้วค่อยปิดเมื่อใช้จริง

### ใช้งาน (พนักงาน)

1. หน้าจ่ายเงิน → เลือกวิธี `QR พร้อมเพย์ (จอลูกค้า)`
2. QR ขึ้นบน**จอลูกค้า**ทันที พร้อมยอดเงินและนับถอยหลังหมดอายุ
   ฝั่งแคชเชียร์ขึ้น "รอลูกค้าสแกน QR บนจอลูกค้า…"
3. ลูกค้าสแกนจ่าย → ระบบตรวจกับ Beam อัตโนมัติทุก 2–3 วินาที → ขึ้น "รับชำระเงินสำเร็จแล้ว"
   และปิด QR บนจอลูกค้าเอง ไม่ต้องกดยืนยัน
4. QR หมดอายุ / ลูกค้าไม่จ่าย → ระบบแจ้งและล้างรายการ กดสร้างใหม่ได้เลย

### ยกเลิกกลางคัน — ต้องรู้

Beam **ไม่มี API ยกเลิก charge แบบ QR** — กด "ยกเลิกรายการ" ฝั่ง POS จะ:
- เช็คก่อนว่าลูกค้าจ่ายไปแล้วหรือยัง (จ่ายแล้ว = ยกเลิกไม่ได้ ระบบบันทึกผลให้)
- ถ้ายัง: ปิดฝั่ง POS และจอลูกค้า **แต่ QR เดิมยังสแกนได้จนหมดอายุ**
  ถ้าลูกค้าเผลอสแกนจ่ายหลังยกเลิก เงินจะเข้า Beam โดยไม่มีบิลใน Odoo —
  ตรวจใน **Beam Lighthouse** แล้วคืนเงินหรือบันทึกรายการตามจริง
- เพราะเหตุนี้อายุ QR จึงตั้งสั้น (120 วิ) — อย่าตั้งยาวโดยไม่จำเป็น

### คืนเงิน

รายการที่จ่ายด้วย Beam QR **คืนผ่าน POS ตรง ๆ ไม่ได้** — ระบบพาเข้าเส้นทางเดิมของร้าน:
คืนเงินใน **Lighthouse** หรือโอนคืน แล้วบันทึกเลขอ้างอิง ≥ 4 ตัวอักษร + ยืนยันเงินออกจริง
ในหน้า "บันทึกการคืนเงิน" (ดู `docs/RUNBOOK-orders-refunds.md`)

## 4. แก้ปัญหา

| อาการ | สาเหตุ / ทางแก้ |
| --- | --- |
| จอลูกค้าไม่อัปเดตตามออเดอร์ | จอเปิดจากลิงก์ของเครื่องแคชเชียร์คนละเครื่อง — เปิดลิงก์ใหม่จากเมนูบนเครื่องปัจจุบัน |
| จอค้างรายการเดิมหลังกลับหน้าโต๊ะ/รายการบิล | แก้แล้วใน 19.0.1.1.0 — ถ้ายังเจอ แปลว่าจอหรือ POS ยังเป็นโค้ดเก่า hard refresh ทั้งสองฝั่ง |
| จอเพิ่งเปิดขึ้นมาแล้วเป็นหน้าต้อนรับ ทั้งที่แคชเชียร์ค้างอยู่หน้าออเดอร์ | ปกติของ Odoo: จอได้ข้อมูลตอน POS มีการเปลี่ยนแปลงถัดไป — คีย์/ลบรายการหนึ่งครั้ง หรือเข้า-ออกโต๊ะ แล้วจอจะตามทัน |
| โฆษณาไม่เล่น | ยังไม่มีไฟล์ที่ "ใช้งาน" ของจุดขายนั้น หรือจอเพิ่งว่างไม่ถึงเวลาที่ตั้ง หรือยังไม่รีเฟรชหลังเพิ่มสื่อ |
| วิดีโอถูกข้าม | ไฟล์เสีย/โหลดไม่ได้ ระบบข้ามอัตโนมัติกันจอค้างดำ — ลอง H.264 MP4 1080p |
| วิดีโอไม่มีเสียง | ตั้งใจ: browser ไม่ให้เล่นเสียงอัตโนมัติ ใช้วิดีโอที่สื่อสารด้วยภาพ/ซับ |
| deploy แล้วจอ/POS ไม่เปลี่ยน | service worker แคชของเก่า — hard refresh ทั้ง POS และจอลูกค้า (ดู `docs/GOTCHAS.md`) |
| QR ไม่ขึ้นบนจอลูกค้า | จอลูกค้าต้องเปิดอยู่ก่อนเลือกวิธีจ่าย และเป็นลิงก์ของเครื่องแคชเชียร์เครื่องนั้น |
| Beam ปฏิเสธ (401/403) | Merchant ID / API Key ผิด หรือสลับ Playground/Production |

## 5. เช็คลิสต์หลัง deploy

1. log มี `DEPLOYED_ko_pos_customer_display` และโมดูลโหลดโดยไม่มี error
2. เปิดจอลูกค้าจากเมนู POS — ออเดอร์ sync, ภาษาไทยครบ, ไม่มี console error
3. อัปโหลดภาพ 1 ไฟล์ → จอว่างครบเวลา → สไลด์ขึ้น → คีย์สินค้า → ตัดกลับทันที
4. Beam QR: ทดสอบใน Playground ก่อน production เสมอ — production คือเงินจริง
   ประสานเจ้าของก่อนยิงยอดจริงทุกครั้ง
